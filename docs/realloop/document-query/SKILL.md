# Ответы по документам

Используй навык, когда по выбранным документам нужно получить файлы с ответами, источниками и диагностикой. Запускай команду из корня репозитория с интерпретатором Python, в котором установлены зависимости проекта. Если исполнитель не видит проект или вложения, уточни их расположение.

1. Возьми файлы текущей задачи и точные формулировки вопросов. Передай каждый путь и каждый вопрос отдельным аргументом. При программном запуске передавай аргументы списком.
2. По умолчанию используй `verified`. Выбирай `baseline`, когда пользователь просит прямой ответ модели.
3. Запусти команду. В примере `python` обозначает интерпретатор подготовленного окружения.

   ```text
   python -m src query --attachment "data/public/packages/P01/01_izveshchenie.txt" --prompt "Кто является заказчиком закупки?" --mode verified
   ```

4. Возьми каталог запуска из последней строки `Отчёт: …` и перечисли созданные в нём файлы из таблицы. Верни их как вложения, доступные следующему шагу. Если исполнитель передаёт ссылки на файлы, укажи доступные абсолютные пути или ссылки на артефакты.
5. Для каждого файла добавь короткое назначение. Содержимое файлов остаётся доступным для чтения последующему агенту, который сам выбирает нужные артефакты.
6. При завершении с техническими ошибками передай доступные файлы и отметь статус запуска. Если команда остановилась до создания результатов, сообщи причину из её вывода.

| Файл | Назначение |
| --- | --- |
| `answers.json` | Структурированные ответы, статусы и цитаты с именами источников. |
| `answers.csv` | Плоская таблица ответов с одной цитатой на вопрос. |
| `report.html` | Отчёт для просмотра в браузере. |
| `manifest.json` | Статус запуска, режим, модель и статистика обработки. |
| `inputs.json` | Вопросы, извлечённый текст документов и сведения об источниках. |
| `prompts.json` | Системные инструкции режимов ответа. |
| `progress.log` | Хронология выполнения. |
| `trace.jsonl` | Подробные события модели, валидации и исправлений. |

Проверяй доступ следующего шага к файлам запуска. `inputs.json` и журналы могут содержать текст документов. Ключ модели берётся из локального `.env` или окружения процесса.
