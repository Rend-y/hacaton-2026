# Подключение ответов по документам к Realloop

Полные инструкции установки проекта и навыка: [Windows](../setup-windows.md), [macOS](../setup-macos.md), [Linux](../setup-linux.md). Готовый навык запускает CLI с API проекта; для модели текущего агента используйте [MCP](../connection-guide.md#mcp).

Агент передаёт инструменту разрешённые файлы, вопросы и режим обработки. После запуска он получает комплект файлов с описанием каждого. Следующий шаг выбирает подходящие файлы для своей задачи. Один и тот же навык можно использовать в любом агентском контуре с доступом к терминалу и подготовленному Python.

## Подготовка инструмента

Установите зависимости по [README проекта](../../README.md#быстрый-старт) и откройте терминал в корне репозитория. В примерах `python` обозначает интерпретатор подготовленного окружения.

```text
python -m src query --help
```

Для обращения к модели задайте `BASE_URL`, `MODEL` и `API_KEY` в локальном `.env`. Укажите HTTPS-адрес OpenAI-совместимого API. [Настройка модели](../../README.md#настройте-модель)

## Подключение к локальному WorkBuddy

1. Подготовьте архив навыка. В корне репозитория выполните команду ниже. В архив попадёт только папка навыка с инструкциями.
2. В WorkBuddy откройте **Experts · Skills · Connectors → Skills → Add Skill → Upload Skill** и выберите `runs/document-query-workbuddy.zip`.
3. Создайте локальную задачу WorkBuddy с рабочей папкой в корне репозитория и выберите установленный навык **Ответы по документам**. Передавайте документы, доступные этой задаче, и явно указывайте вопросы. [Импорт навыков WorkBuddy](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills-Market#上传技能) · [Рабочая папка и выбор навыка](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Task-Bar)

```text
python -c "from pathlib import Path; Path('runs').mkdir(exist_ok=True)"
python -m zipfile -c runs/document-query-workbuddy.zip docs/realloop/document-query
```

[Исходник навыка](document-query/SKILL.md) описывает запуск `query` и передачу файлов. Для пробного запуска отправьте агенту запрос.

> Используй навык «Ответы по документам» в режиме verified. По файлу data/public/packages/P01/01_izveshchenie.txt задай вопрос, кто заказчик закупки и что нужно разработать. Верни файлы запуска с описанием каждого.

Ожидаемые факты для этого примера — заказчик ГКУ «Многофункциональный центр-Пример» и разработка чат-бота для приёма обращений граждан. Ответ берётся из первых строк [извещения P01](../../data/public/packages/P01/01_izveshchenie.txt).

Тот же запрос можно выполнить напрямую из корня репозитория.

```text
python -m src query --attachment "data/public/packages/P01/01_izveshchenie.txt" --prompt "Кто является заказчиком закупки и что нужно разработать?" --mode verified
```

## Контракт для внутреннего агентского контура

Если Realloop у вас представляет собой внутренний агентский цикл, зарегистрируйте инструмент `answer_from_documents` в его реестре инструментов. Реализацию возьмите из [Python-примера с run_query](../agent-integration.md#подключение-всего-режима-verified-как-инструмента). Если исполнитель умеет запускать только процессы, передавайте аргументы списком и вызывайте `python -m src query` с рабочим каталогом репозитория.

Вход инструмента можно задать таким JSON Schema.

```json
{
  "type": "object",
  "properties": {
    "document_ids": {
      "type": "array",
      "minItems": 1,
      "items": {"type": "string", "minLength": 1}
    },
    "questions": {
      "type": "array",
      "minItems": 1,
      "maxItems": 200,
      "items": {"type": "string", "minLength": 1, "maxLength": 10000}
    }
  },
  "required": ["document_ids", "questions"],
  "additionalProperties": false
}
```

1. Бэкенд сопоставляет каждый `document_id` с разрешённым локальным файлом. В режиме вызова из терминала он передаёт каждый файл отдельным аргументом после `--attachment`, а каждый вопрос отдельным аргументом после `--prompt`. Вариант с Python-адаптером передаёт списки в `QueryOptions`.
2. Адаптер запускает `verified`. Этот режим сверяет цитаты, числа и даты с документами и при ошибках запрашивает исправление. Для длительной обработки используйте фоновую задачу и возвращайте её идентификатор агенту.
3. При вызове CLI возьмите каталог запуска из последней строки `Отчёт: …`. При вызове Python используйте каталог, переданный в `output`. Передайте следующему агенту созданные в нём файлы как вложения или доступные ссылки. Добавьте к каждому файлу назначение из таблицы ниже.
4. Код `0` означает завершение. Код `2` с файлами результата означает, что часть ответов содержит технические ошибки. В этом случае передайте доступные файлы и отметьте статус. При ошибке до создания файлов передайте причину из вывода команды.

| Файл | Назначение |
| --- | --- |
| `answers.json` | Структурированные ответы, статусы, цитаты и имена источников. |
| `answers.csv` | Таблица для импорта или сравнения ответов. Содержит одну цитату на вопрос. |
| `report.html` | Отчёт для просмотра в браузере. |
| `manifest.json` | Статус запуска, режим, модель, настройки и статистика обработки. |
| `inputs.json` | Вопросы, извлечённый текст документов и сведения об источниках. |
| `prompts.json` | Системные инструкции режимов ответа. |
| `progress.log` | Хронология выполнения. |
| `trace.jsonl` | Подробные события запросов, валидации и исправлений. |

На сервере храните `.env` отдельно от файлов навыка. Текст выбранных документов отправляется провайдеру модели, заданному в `BASE_URL`. Перед вызовом проверяйте доступ к документам, а при передаче файлов — доступ к результатам этого запуска.
