# Linux: установка и запуск

[Общее руководство](connection-guide.md) · [Windows](setup-windows.md) · [macOS](setup-macos.md) · [Linux](setup-linux.md)

После этих шагов вы сможете задавать вопросы из командной строки, работать с дашбордом, подключить MCP к агенту и установить готовый skill. Терминал: терминал с bash. Для дашборда нужен браузер; на сервере без графической среды можно использовать CLI или SSH-туннель.

CLI — командная строка проекта (`python -m src`). MCP — инструменты для модели вашего агента. Skill — инструкция для агента, как запускать CLI и передавать результаты. Дашборд — локальный интерфейс в браузере. Их можно использовать независимо.

## 1. Установите Python и Git

Нужны Git, Python 3.10+ и модуль `venv`. Команда установки зависит от дистрибутива; выберите один подходящий вариант.

**Ubuntu / Debian:**

```bash
sudo apt update
sudo apt install git python3 python3-venv python3-pip
```

**Fedora:**

```bash
sudo dnf install git python3 python3-pip
```

Проверьте результат:

```bash
git --version
python3 --version
python3 -m venv --help
```

Если Python старше 3.10, используйте поддерживаемую версию дистрибутива или отдельно установленный Python 3.10+. Для другого дистрибутива установите эквивалентные пакеты его пакетным менеджером. Не заменяйте системный `/usr/bin/python3` вручную.

Официальные инструкции: [Python на Ubuntu](https://ubuntu.com/developers/docs/howto/python-setup/) и [Python на Fedora](https://developer.fedoraproject.org/tech/languages/python/python-installation.html). `sudo` требуется только для системных пакетов; дальнейшие действия выполняются обычным пользователем.

## 2. Откройте репозиторий

Для новой установки:

```bash
mkdir -p "$HOME/projects"
cd "$HOME/projects"
git clone https://github.com/Rend-y/hacaton-2026.git
cd hacaton-2026
git branch --show-current
```

Ожидаемая ветка — `main`. Если проект уже скачан, повторно клонировать его не нужно. Перейдите в свою папку:

```bash
cd "/путь/к/вашему/репозиторию"
git status --short --branch
```

Все следующие команды выполняются из корня проекта. В нём должны быть `src/`, `run_mcp.py`, `requirements.txt` и `.env.example`. Пути с пробелами заключайте в кавычки. Если Git показывает несохранённые изменения, сохраните или разберите их перед сменой ветки и обновлением; не сбрасывайте их ради установки.

## 3. Подготовьте окружение

Если рабочая `.venv` уже существует, пропустите команду её создания. Не копируйте `.venv` между операционными системами и папками: создавайте её на нужной машине. Устройство окружений описано в [документации Python](https://docs.python.org/3.12/library/venv.html).

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements.txt -r requirements-mcp.txt -r requirements-pdf.txt
test -f .env || cp .env.example .env
```

Команда установки включает основные библиотеки, MCP и чтение PDF. Если MCP или PDF не нужны, соответствующий `-r requirements-mcp.txt` или `-r requirements-pdf.txt` можно убрать. Создание `.env` сохраняет уже существующие настройки.

Если используется отдельно установленный Python, замените `python3` в первой команде на его путь или имя, например `python3.12`. У пакета `venv` должна быть та же версия, что у выбранного интерпретатора.

Активация окружения не обязательна. Не устанавливайте зависимости проекта через `sudo pip` и не используйте `--break-system-packages`: команды с `.venv/bin/python -m pip` устанавливают библиотеки в окружение проекта.

Проверьте установку без обращения к модели:

```bash
.venv/bin/python --version
.venv/bin/python -m pip check
.venv/bin/python -m src --help
.venv/bin/python run_mcp.py --help
.venv/bin/python -m src.dashboard --help
```

`pip check` должен сообщить об отсутствии конфликтов зависимостей, остальные команды — показать версию или справку. До настройки API эти проверки уже должны работать. Если одна команда завершилась ошибкой, устраните её перед следующим шагом.

## 4. Настройте модель для CLI и дашборда

Этот шаг нужен также для существующего skill, который запускает CLI. Для MCP модель предоставляет клиент: заполнение API-полей проекта для него не требуется.

Откройте `.env`:

```bash
nano .env
```

Если `nano` установлен, сохраните файл через `Ctrl+O`, `Enter` и выйдите через `Ctrl+X`. Иначе откройте `.env` любым текстовым редактором. Заполните реальные значения своего OpenAI-совместимого провайдера:

```dotenv
BASE_URL=https://api.example.com/v1
MODEL=your-model-id
API_KEY=your-api-key
TEMPERATURE=0
```

`api.example.com`, `your-model-id` и `your-api-key` — примеры, их нужно заменить. В `BASE_URL` укажите базовый HTTPS-адрес без `/chat/completions`. Оставьте остальные параметры шаблона, затем при необходимости задайте реальный лимит контекста модели. `MAX_TOKENS` должен быть меньше `CONTEXT_TOKEN_LIMIT`. Переменные окружения процесса имеют приоритет над `.env`.

## 5. Задайте вопрос через CLI

В проекте есть демонстрационные документы — свои файлы для первой проверки не нужны:

```bash
.venv/bin/python -m src query --attachment "data/public/packages/P01/01_izveshchenie.txt" --prompt "Кто является заказчиком закупки?" --mode verified
```

Ожидаемый заказчик — ГКУ «Многофункциональный центр-Пример». Успешный запуск выведет ответ и путь к `report.html`. Откройте этот файл в браузере; рядом лежат `answers.json`, `answers.csv` и журналы.

Для нескольких документов и вопросов:

```bash
.venv/bin/python -m src query --attachment "Договор.docx" "Условия.txt" --prompt "Какой срок выполнения работ?" "Какой гарантийный срок?" --mode verified
```

Замените имена файлов на существующие пути. Все вопросы относятся ко всему переданному комплекту. `verified` включён по умолчанию и проверяет цитаты, числа и даты; `baseline` оставляет прямой ответ модели. Полный список аргументов:

```bash
.venv/bin/python -m src query --help
```

Текст документов передаётся провайдеру из `.env`. Прохождение локальных проверок не гарантирует полноту смысла ответа; для нескольких цитат смотрите `answers.json`, поскольку CSV сохраняет одну цитату на вопрос.

## 6. Запустите дашборд

```bash
.venv/bin/python -m src.dashboard
```

Оставьте этот терминал работающим. В браузере откройте [http://127.0.0.1:8765](http://127.0.0.1:8765). Из второго терминала можно открыть адрес командой:

```bash
xdg-open 'http://127.0.0.1:8765'
```

В **Настройках** проверьте модель и API. В **Новой обработке** выберите документы, введите вопросы по одному на строку и запустите обработку. В **Обработках** доступны прогресс, история и отчёты; в **Тестовых наборах** — вопросы с эталонами и сравнение режимов; в **Подключении MCP** — пример конфигурации.

Если порт занят:

```bash
.venv/bin/python -m src.dashboard --port 8766
```

Тогда откройте `http://127.0.0.1:8766`. Для остановки сервера нажмите `Ctrl+C` в его терминале после завершения обработки. Настройки сохраняются в `.env` и применяются к новым запускам. Пустое поле API-ключа в интерфейсе сохраняет текущий ключ.

### Дашборд на удалённом Linux

Если сервер запущен на другой машине, `127.0.0.1` в вашем браузере указывает на ваш компьютер. Оставьте дашборд работающим на сервере и в отдельном локальном терминале создайте туннель, заменив `user@server` своими данными:

```bash
ssh -N -L 8765:127.0.0.1:8765 user@server
```

Теперь откройте `http://127.0.0.1:8765` на своём компьютере. При занятом локальном порте используйте `-L 8766:127.0.0.1:8765` и адрес с портом 8766. Остановите туннель через `Ctrl+C` после работы. Такое перенаправление относится к веб-интерфейсу, а локальный MCP STDIO подключается к процессу на машине клиента.

## 7. Подключите MCP

### Что требуется клиенту

Нужен агент, который умеет запускать локальные MCP-серверы по **STDIO** и выполнять цикл инструментов. Клиент и репозиторий в этом сценарии находятся на одной машине. Веб-клиент, принимающий только HTTP URL, напрямую не подключится к `run_mcp.py`. Адрес дашборда не является MCP endpoint.

MCP-клиент сам запускает сервер. Дашборд и отдельный процесс `run_mcp.py` заранее запускать не нужно. Серверу нужны абсолютные пути к Python окружения и `run_mcp.py`; переменные вроде `$HOME` и `~` внутри JSON не подставляйте.

### Создайте конфигурацию с вашими путями

В корне репозитория выполните команду. Она только печатает JSON и не изменяет настройки клиента:

```bash
.venv/bin/python -c 'import json; from pathlib import Path; p=Path.cwd(); print(json.dumps({"mcpServers":{"document-agent":{"command":str(p/".venv/bin/python"),"args":[str(p/"run_mcp.py")]}}}, indent=2))'
```

Если клиент использует формат `mcpServers`, добавьте напечатанную запись `document-agent` в его MCP-конфигурацию, сохранив другие серверы. Если клиент предлагает форму, перенесите поле `command` в команду запуска, а единственный элемент `args` — в аргумент. Выберите STDIO. Точное расположение конфигурации определяется клиентом.

### Регистрация через Codex CLI

Если установлен Codex CLI, можно выполнить вместо ручного редактирования конфигурации:

```bash
codex mcp add document-agent -- "$PWD/.venv/bin/python" "$PWD/run_mcp.py"
codex mcp list
```

Это команда внешнего клиента `codex`, а не CLI проекта. Если она не найдена, установите клиент или используйте его интерфейс настройки MCP. Переподключите сервер после регистрации. Формат команды описан в [официальной документации Codex](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

### Проверьте полный цикл

Отправьте агенту:

> Через document-agent вызови list_document_sets, выбери P01 и узнай способ определения поставщика. Выполни все запросы модели и исправления до завершения, затем покажи проверенный ответ с цитатой.

Ожидается «электронный аукцион». Агент получает ID комплекта из `list_document_sets`, вызывает `ask_documents`, при `requires_response` отвечает на `model_request.messages` и передаёт JSON строкой через `submit_document_response`. При `running` запрашивает `get_document_run`. Итог публикуется после `completed` или `completed_with_errors`. Одного появления инструментов в клиенте недостаточно для проверки полного сценария.

Для вложений текущего чата агент создаёт `chat_id` через `create_document_chat`, загружает файлы и сохраняет этот ID для дальнейших вызовов. Если клиент не умеет передавать байты вложений, попросите его показать созданный ID и загрузите файлы:

```bash
.venv/bin/python -m src upload-documents --chat-id "<chat_id>" --attachment "Договор.docx" "Условия.txt"
```

Замените `<chat_id>` реальным ID. После этого агент вызывает `get_document_chat` и выбирает `attachment_ids`. Для нового разговора нужен отдельный контекст. Загрузка не вызывает модель.

MCP работает только в режиме `verified`, использует модель клиента и не читает API-настройки генерации из `.env`. Документы обрабатываются провайдером модели клиента. Подробности инструментов, состояний и хранения — в [общем руководстве](connection-guide.md#mcp).

## 8. Установите skill

В репозитории есть готовый [`document-query`](realloop/document-query/SKILL.md). Он запускает CLI, поэтому ему нужны настроенный `.env`, доступ к файлам и терминал. Установка skill не подключает MCP; для сценария MCP достаточно подключения сервера и обработки его инструментов агентом.

### Для Codex в этом репозитории

```bash
mkdir -p .agents/skills
if [ ! -e .agents/skills/document-query ]; then
  cp -R docs/realloop/document-query .agents/skills/document-query
else
  echo 'Навык уже установлен: проверьте существующую копию.'
fi
test -f .agents/skills/document-query/SKILL.md && echo 'SKILL.md найден'
```

Последняя команда подтверждает наличие файла. Если папка уже была, сначала сравните установленный навык с исходным, не затирайте локальные изменения. Откройте задачу Codex в корне репозитория; при необходимости перезапустите клиент. Путь `.agents/skills` описан в [документации Skills](https://learn.chatgpt.com/docs/build-skills).

Проверочный запрос:

> Используй document-query в режиме verified. Запусти CLI через Python из .venv и по data/public/packages/P01/01_izveshchenie.txt выясни, кто заказчик. Верни ответ с цитатой и файлы результата с пояснениями.

### Для клиента с импортом ZIP

```bash
.venv/bin/python -c "from pathlib import Path; Path('runs').mkdir(exist_ok=True)"
.venv/bin/python -m zipfile -c runs/document-query-workbuddy.zip docs/realloop/document-query
```

Импортируйте `runs/document-query-workbuddy.zip` через механизм Skills клиента. Укажите рабочую папку репозитория и интерпретатор `.venv/bin/python`. Инструкция для [WorkBuddy и Realloop](realloop/README.md) описывает этот сценарий подробнее.

## 9. Повторный запуск и обновление

После закрытия терминала достаточно снова перейти в репозиторий и использовать Python из `.venv`. Повторно устанавливать зависимости при каждом запуске не нужно. После обновления кода, когда локальные изменения сохранены и рабочее дерево чистое:

```bash
git status --short --branch
git pull --ff-only
.venv/bin/python -m pip install -r requirements.txt -r requirements-mcp.txt -r requirements-pdf.txt
.venv/bin/python -m pip check
```

Выполняйте команды по очереди. Если `git pull` остановился из-за локальных изменений или расхождения веток, сначала разберите это состояние. Затем перезапустите дашборд и переподключите MCP, чтобы процессы загрузили новый код. При обновлении исходного skill обновите установленную копию, сохранив собственные правки. При переносе проекта в другую папку обновите абсолютные пути MCP и создайте окружение в новом месте.

## Типичные проблемы

| Симптом | Решение |
| --- | --- |
| `No module named venv` или `ensurepip is not available` | На Ubuntu/Debian установите `python3-venv`, а для отдельной версии — соответствующий пакет, например `python3.12-venv`, если он доступен в вашей системе. Повторите создание `.venv`. |
| `externally-managed-environment` | Вызывайте `.venv/bin/python -m pip`, а не системный `pip`. |
| `Permission denied` при записи `.venv` | Выберите доступный пользователю каталог проекта; не запускайте проект через `sudo`. |
| Нет команды `xdg-open` | Откройте адрес в браузере вручную; на удалённой машине используйте SSH-туннель. |
| `No module named src` | Перейдите в корень репозитория, где находятся `src/` и `requirements.txt`. |
| `No module named mcp` | Установите `requirements-mcp.txt` через Python, указанный в конфигурации MCP-клиента. |
| `No module named src` при прямом вызове | Выполняйте `-m src` из корня репозитория. Для MCP используйте абсолютный путь к `run_mcp.py`. |
| Ответ не появляется после `requires_response` | Агент должен вызвать `submit_document_response`; ожидание и опрос состояния не генерируют ответ. |
| «Запуск не найден» | Для чатового запуска нужен исходный `chat_id` вместе с `run_id`. |
| PDF не содержит текста | Установите PDF-зависимости и проверьте текстовый слой. Распознавания сканов OCR в проекте нет. |
| Ошибка доступа к API | Проверьте базовый HTTPS-адрес, модель, ключ и приоритет переменных окружения. |
| Ошибка установки бинарного пакета | Проверьте версию и архитектуру Python, обновление pip и доступность пакета для этой платформы. Не переносите чужую `.venv`. |

Для разбора конкретного запуска используйте `progress.log`, `trace.jsonl` и `manifest.json`. [Общее руководство](connection-guide.md#результаты-и-ограничения) описывает расположение результатов и ограничения файлов. При обращении за помощью сообщите ОС, версию Python, точную команду и текст ошибки без API-ключа.
