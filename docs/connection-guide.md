# Подключение проекта: MCP, Skills, CLI и дашборд

Проект отвечает на вопросы по выбранным документам и сохраняет ответы, цитаты и отчёт. Это руководство помогает установить зависимости, выбрать способ работы и проверить подключение. Команды выполняются из корня репозитория, если явно не указано иное.

## Выбор способа работы

| Способ | Когда использовать | Кто генерирует ответ | Что настроить |
| --- | --- | --- | --- |
| [MCP](#mcp) | Вопросы и вложения в чате агента | Модель MCP-клиента | Python проекта и локальный сервер STDIO |
| [Skills](#skills) | Повторяемый сценарий для агента с терминалом | Через CLI — провайдер из `.env` | Готовый навык `document-query`, CLI и API |
| [CLI](#cli) | Запуск из терминала или скрипта | Провайдер из `.env` | `BASE_URL`, `MODEL`, `API_KEY` |
| [Дашборд](#дашборд) | Загрузка документов, история и тестовые наборы в браузере | Провайдер из `.env` | Те же настройки API и локальный веб-сервер |

Для MCP отдельный ключ модели в проекте не нужен. Сервер использует ответы подключённого агента через цикл инструментов. Установка навыка не подключает MCP автоматически: существующий навык проекта запускает CLI. Дашборд не требуется для работы MCP.

## Установка

Для первого запуска откройте инструкцию своей операционной системы. Каждая проходит весь путь: Python и Git → репозиторий → окружение → модель → CLI → дашборд → MCP → skill → обновление и диагностика.

| Операционная система | Пошаговая инструкция | Терминал |
| --- | --- | --- |
| Windows | [Установка и запуск на Windows](setup-windows.md) | PowerShell; основной сценарий без изменения Execution Policy. |
| macOS | [Установка и запуск на macOS](setup-macos.md) | Terminal, zsh или bash; Homebrew или готовый Python. |
| Linux | [Установка и запуск на Linux](setup-linux.md) | bash; пакеты для Ubuntu/Debian и Fedora, доступ к удалённому дашборду. |

Код проекта требует Python 3.10+. Зависимости устанавливаются отдельно на каждой машине в `.venv`; перенос готового окружения между ОС не поддерживается. Основные пакеты перечислены в `requirements.txt`, MCP — в `requirements-mcp.txt`, чтение PDF — в `requirements-pdf.txt`.

Ниже приведён общий справочник по устройству интеграций. Полные команды для выбранной ОС находятся в её инструкции: заменять Windows-пути вручную не нужно.

## MCP

### Подключение локального сервера

Сервер `document-agent` поддерживает **STDIO**: MCP-клиент запускает Python-процесс и обменивается сообщениями через стандартные потоки. Укажите абсолютные пути к Python окружения и `run_mcp.py`. Рабочий каталог клиента может отличаться от каталога проекта.

Для клиента, использующего JSON с разделом `mcpServers`, добавьте запись:

```json
{
  "mcpServers": {
    "document-agent": {
      "command": "C:/projects/hacaton-2026/.venv/Scripts/python.exe",
      "args": ["C:/projects/hacaton-2026/run_mcp.py"]
    }
  }
}
```

Замените `C:/projects/hacaton-2026` в обоих путях на расположение своего репозитория. Существующие записи других серверов сохраняйте. На Linux/macOS используйте пути вида `/home/user/hacaton-2026/.venv/bin/python` и `/home/user/hacaton-2026/run_mcp.py`.

Запуском сервера управляет клиент. Не нужно предварительно запускать `run_mcp.py` в отдельном терминале или задавать URL дашборда в качестве MCP-адреса. Порт `8765` обслуживает браузер; HTTP-транспорт MCP в этой реализации не предоставляется.

### Пример для Codex

Если Codex CLI установлен, из корня проекта выполните:

```powershell
$projectPath = (Get-Location).Path
codex mcp add document-agent -- "$projectPath/.venv/Scripts/python.exe" "$projectPath/run_mcp.py"
codex mcp list
```

На Linux/macOS:

```bash
codex mcp add document-agent -- "$PWD/.venv/bin/python" "$PWD/run_mcp.py"
codex mcp list
```

Переподключите сервер в клиенте или перезапустите клиент, чтобы обновился список инструментов. Синтаксис регистрации и просмотра серверов описан в [официальной документации Codex MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

### Проверка подключения

Попросите агента:

> Через document-agent вызови list_document_sets, выбери демонстрационный комплект P01 и выясни, какой способ определения поставщика указан в извещении. Заверши цикл проверки и верни итоговый ответ с цитатой.

Ожидаемый факт — «электронный аукцион» из `data/public/packages/P01/01_izveshchenie.txt`. ID комплекта берётся из результата `list_document_sets`; агент не должен придумывать его. Успешный вызов списка проверяет соединение, а завершённый ответ с цитатой — полный цикл работы.

### Инструменты и цикл ответа

| Инструмент | Назначение |
| --- | --- |
| `list_document_sets` | Посмотреть демонстрационные и ранее загруженные комплекты. |
| `create_document_chat` | Создать пустой контекст вложений нового чата и получить `chat_id`. |
| `upload_documents` | Загрузить байты файлов в Base64 в чат (`chat_id`) или отдельный комплект (`title`). |
| `get_document_chat` | Получить вложения чата и их `attachment_id`. |
| `ask_documents` | Начать ответ по `chat_id` или `document_set_id`; для чата можно выбрать `attachment_ids`. |
| `submit_document_response` | Передать JSON-ответ модели строкой `response` для конкретных `run_id` и `request_id`. |
| `get_document_run` | Получить следующий запрос модели, состояние или проверенные ответы. |

Обычный сценарий для вложений: `create_document_chat` → `upload_documents` → `get_document_chat` → `ask_documents`. Для нового разговора создаётся новый `chat_id`; для продолжения используется ID этого разговора. В `ask_documents` передаётся ровно один контекст: `chat_id` или `document_set_id`.

После запуска агент обрабатывает состояния:

1. `requires_response`: выполняет `model_request.messages` своей моделью и передаёт JSON строкой через `submit_document_response`. Берёт `request_id` из текущего запроса.
2. `running`: проверяет состояние через `get_document_run`.
3. `completed` или `completed_with_errors`: показывает сохранённые `answers`; при технических отказах сообщает их причины.
4. `unknown` или `failed`: сообщает ошибку. После перезапуска сервера незавершённую обработку нужно начать заново; сохранённые документы остаются доступны.

Во всех вызовах получения состояния и передачи ответа для чатового запуска нужен тот же `chat_id`. Вызовы повторяются для следующих групп вопросов и исправлений. Пользователь задаёт обычный вопрос — обмен JSON выполняет агент.

MCP всегда использует `verified`; сервер проверяет ответ и допускает до двух исправлений. MCP Sampling не требуется. На один ожидаемый ответ клиента отводится 15 минут. Сервер не вызывает API генерации и не использует настройки модели из `.env`. Лимит контекста MCP задаётся кодом; увеличение `CONTEXT_TOKEN_LIMIT` в `.env` относится к CLI и дашборду, а не к MCP.

### Если клиент не передаёт вложения

Попросите агента создать чат и показать его `chat_id`, затем загрузите документы через CLI:

```powershell
.\.venv\Scripts\python.exe -m src upload-documents --chat-id "<chat_id>" --attachment "Договор.docx" "Условия.txt"
```

После загрузки агент должен обновить список через `get_document_chat`. Вместо чата можно создать отдельный комплект:

```powershell
.\.venv\Scripts\python.exe -m src upload-documents --title "Договор и условия" --attachment "Договор.docx" "Условия.txt"
```

Команда возвращает JSON с `document_set_id`. Передайте этот ID агенту для `ask_documents`. Выбирайте `--title` либо `--chat-id`, одновременно они не принимаются. Загрузка сама по себе не вызывает модель и не требует API-ключа.

Подробности адаптера и локального валидатора: [интеграция с агентским циклом](agent-integration.md).

## Skills

Готовый навык находится в [`docs/realloop/document-query/SKILL.md`](realloop/document-query/SKILL.md). Он учит агента запускать `query` и возвращать файлы результата с описанием. Для него нужны терминал, доступ к репозиторию и документам, Python проекта и настроенный API из раздела [CLI](#cli).

### Установка навыка в Codex

Из корня репозитория скопируйте папку навыка в каталог локальных навыков проекта:

```powershell
$skillPath = '.agents/skills/document-query'
if (Test-Path -LiteralPath $skillPath) { throw 'Навык уже существует: сначала проверьте его содержимое.' }
New-Item -ItemType Directory -Path '.agents/skills' -Force | Out-Null
Copy-Item -LiteralPath 'docs/realloop/document-query' -Destination $skillPath -Recurse
```

На Linux/macOS:

```bash
mkdir -p .agents/skills
if [ ! -e .agents/skills/document-query ]; then
  cp -R docs/realloop/document-query .agents/skills/document-query
else
  echo 'Навык уже существует: сначала проверьте его содержимое.'
fi
```

Откройте задачу агента в корне этого репозитория. Если навык не появился, перезапустите Codex. Расположение `.agents/skills` и обнаружение навыков описаны в [официальном руководстве по Skills](https://learn.chatgpt.com/docs/build-skills). При обновлении исходного `SKILL.md` обновляйте установленную копию после проверки локальных изменений.

### WorkBuddy и другие агенты

Если клиент импортирует навыки архивом, подготовьте архив из корня проекта:

```powershell
.\.venv\Scripts\python.exe -c "from pathlib import Path; Path('runs').mkdir(exist_ok=True)"
.\.venv\Scripts\python.exe -m zipfile -c runs/document-query-workbuddy.zip docs/realloop/document-query
```

Импортируйте архив через механизм Skills клиента, задайте рабочую папку проекта и выберите навык. Для WorkBuddy и Realloop есть [отдельная инструкция](realloop/README.md).

Проверочный запрос:

> Используй навык document-query в режиме verified. Через Python окружения .venv обработай data/public/packages/P01/01_izveshchenie.txt и выясни, кто заказчик и что нужно разработать. Верни ответы с источниками и файлы результата с описанием.

В P01 указаны ГКУ «Многофункциональный центр-Пример» и разработка чат-бота для приёма обращений граждан. Этот запуск использует API проекта. Если нужен ответ именно моделью текущего агента, выбирайте сценарий MCP выше: инструкции цикла сервер передаёт клиенту при подключении, отдельного MCP-навыка в репозитории сейчас нет.

## CLI

### Настройка модели

Для генерации заполните `.env` в корне проекта:

```dotenv
BASE_URL=https://api.example.com/v1
MODEL=your-model-id
API_KEY=your-api-key
TEMPERATURE=0
```

Это шаблон: замените адрес, модель и ключ значениями своего OpenAI-совместимого провайдера. `BASE_URL` должен быть базовым HTTPS-адресом API, без `/chat/completions` в конце. Переменные окружения процесса имеют приоритет над `.env`. Ключ хранится локально, в документацию и конфигурацию навыка его добавлять не нужно.

Для больших комплектов укажите реальный `CONTEXT_TOKEN_LIMIT` модели; `MAX_TOKENS` должен быть положительным и меньше него. Другие параметры перечислены в [`.env.example`](../.env.example) и [README](../README.md#большие-документы).

### Первый запуск

```powershell
.\.venv\Scripts\python.exe -m src query --attachment "data/public/packages/P01/01_izveshchenie.txt" --prompt "Кто является заказчиком закупки?" --mode verified
```

В PowerShell доступна обёртка `.\run.ps1 query ...`. Несколько файлов и вопросов передаются отдельными аргументами:

```powershell
.\.venv\Scripts\python.exe -m src query --attachment "Договор.docx" "Условия.txt" --prompt "Какой срок выполнения работ?" "Какой гарантийный срок?" --mode verified
```

Все вопросы относятся ко всему переданному комплекту. `verified` включён по умолчанию: проверяет цитаты, числа и даты, запрашивает исправления. `baseline` сохраняет прямые ответы модели без содержательной проверки. Справка:

```powershell
.\.venv\Scripts\python.exe -m src query --help
.\.venv\Scripts\python.exe -m src upload-documents --help
```

CLI сообщает путь к отчёту. Код `0` означает завершённый запуск; `1` — ошибку чтения, конфигурации или API, обработанную точкой входа; `2` — ошибку аргументов либо завершение обработки с техническими отказами; `130` — прерывание пользователем. Для кода `2` смотрите вывод и наличие результатов: сам код не означает, что отчёт обязательно создан.

## Дашборд

Запустите сервер из корня репозитория:

```powershell
.\.venv\Scripts\python.exe -m src.dashboard
```

Откройте [http://127.0.0.1:8765](http://127.0.0.1:8765). На Linux/macOS команда — `.venv/bin/python -m src.dashboard`. Если порт занят, добавьте `--port 8766` и откройте соответствующий адрес. Сервер привязан к `127.0.0.1`.

1. В **Настройках** задайте API, модель и лимиты. Они сохраняются в `.env` и применяются к новым запускам. Пустое поле ключа сохраняет текущий ключ; параметры из окружения процесса меняются через окружение.
2. В **Новой обработке** добавьте документы и вопросы, по одному вопросу на строку, затем запустите обработку.
3. В **Обработках** следите за прогрессом и открывайте отчёты сохранённых запусков.
4. В **Тестовых наборах** создавайте наборы с эталонами и запускайте сравнение режимов. Оценка по эталону — отдельная проверка качества.
5. На странице **Подключение MCP** копируйте пример локальной конфигурации и проверочный запрос.

Держите процесс сервера запущенным до завершения обработки. Для остановки используйте `Ctrl+C` в его терминале. Запуск веб-интерфейса и просмотр существующих результатов не требуют генерации; обработка новых вопросов использует API из `.env`.

`RUN_INPUT_RETENTION_HOURS` задаёт срок хранения временных копий входов завершённых запусков дашборда: по умолчанию 24 часа, `0` отключает очистку. Это настройка временных входов дашборда, а не общий срок удаления всех отчётов и MCP-чатов.

## Результаты и ограничения

| Где | Что сохраняется |
| --- | --- |
| `runs/<каталог запуска>/` | Результаты CLI и обычных обработок дашборда. |
| `runs/.dashboard/` | Служебные данные и загруженные входы дашборда. |
| `runs/.agent/chats/<chat_id>/` | Вложения MCP-чатов. |
| `runs/.agent/documents/` | Отдельные загруженные комплекты MCP. |
| `runs/.agent/queries/<run_id>/` | Результаты MCP-обработки. |
| `test-data/` | Сохранённые тестовые наборы с вопросами и эталонами. |

В каталоге результата находятся `answers.json`, `answers.csv`, `report.html`, `manifest.json`, `inputs.json`, `prompts.json`, `progress.log` и `trace.jsonl`. Для полного набора цитат используйте `answers.json`: CSV содержит одну цитату на вопрос и может не охватывать обе стороны расхождения или все основания расчёта.

Поддерживаются TXT, Markdown, RST, CSV, JSON, HTML, DOCX и PDF с текстовым слоем. OCR не выполняется. Основные пределы: до 500 документов, 20 МиБ на файл, 80 МиБ суммарно, до 2 млн символов извлечённого текста на файл; для PDF — до 300 страниц. До 200 вопросов за запрос, до 10 000 символов на вопрос. Действуют также ограничения контекста модели.

При работе через CLI и дашборд документы передаются настроенному API, через MCP — модели клиента. Входные снимки и журналы могут содержать текст документов. `verified` проверяет формальные подтверждения; соответствие цитаты всему смыслу ответа, полнота поиска и выбор применимой редакции требуют отдельной оценки. Инструкции, найденные внутри документов, рассматриваются как данные источника, а не команды агенту.

## Диагностика

| Симптом | Что проверить |
| --- | --- |
| `No module named mcp` | Установите `requirements-mcp.txt` тем Python, который указан в конфигурации клиента. |
| MCP не появляется в клиенте | Проверьте оба абсолютных пути, запуск `run_mcp.py --help` и выбранный транспорт STDIO; переподключите сервер. |
| Вручную запущенный `run_mcp.py` ждёт ввода | Это процесс протокола STDIO. Подключите его через MCP-клиент. |
| Есть `requires_response`, но нет ответа | Агент должен обработать `model_request.messages` и вызвать `submit_document_response`, а не только опрашивать состояние. |
| «Запуск не найден» | Для чатового запуска передавайте исходный `chat_id` вместе с `run_id`. |
| «Запрос уже обработан или устарел» | Получите текущее состояние и используйте актуальный `request_id`. |
| `unknown` после перезапуска | Повторите `ask_documents` по сохранённым документам. |
| Ошибка контекста MCP | Выберите меньше файлов через `attachment_ids` или разделите задачу; настройки API в `.env` не меняют MCP-лимиты. |
| CLI/дашборд сообщают об API | Проверьте `.env`, приоритет окружения, базовый HTTPS-адрес, модель и ключ. |
| PDF не читается | Установите `requirements-pdf.txt` и убедитесь, что PDF содержит текстовый слой. |
| Порт дашборда занят | Используйте `--port 8766` или другой свободный порт. |
| Навык не виден или запускает другой Python | Проверьте путь `.agents/skills/document-query/SKILL.md`, рабочую папку агента и выбор Python из `.venv`. |

Для диагностики конкретной обработки откройте `progress.log`, `trace.jsonl` и `manifest.json` её каталога. При передаче логов учитывайте, что они могут содержать исходные документы.
